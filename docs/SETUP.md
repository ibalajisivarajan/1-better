# Setup Guide — 1% Better

This guide walks through every step needed to deploy a fully working instance of 1% Better from scratch. Follow the steps in order.

Estimated time: 45–60 minutes on first setup.

---

## Prerequisites

- A GitHub account (for the repo and Actions)
- A Google account (for Google OAuth sign-in)
- A Vercel account (free tier is sufficient)
- A Supabase account (free tier is sufficient)
- Node.js 18+ installed locally
- The Supabase CLI installed: `npm install -g supabase`

---

## Step 1: Create the Supabase project

1. Go to [app.supabase.com](https://app.supabase.com) and sign in.
2. Click **New project**.
3. Choose your organization, name the project `1-better`, and select the region nearest to you.
4. Choose a strong database password (save it somewhere safe — you will not need it often, but it cannot be recovered).
5. Click **Create new project** and wait for provisioning (about 30–60 seconds).
6. Once the project is ready, go to **Project Settings → API**.
7. Note down:
   - **Project URL** (e.g. `https://abcdefgh.supabase.co`)
   - **anon / public key** (safe to expose in the browser)
   - **service_role / secret key** (never expose this — needed for Step 6)

---

## Step 2: Run the database migration and seed

1. In your Supabase dashboard, go to **SQL Editor** (left sidebar).
2. Click **New query**.
3. Open `supabase/migrations/0001_init.sql` in this repo. Paste the entire contents into the SQL editor.
4. Click **Run** (or press Ctrl+Enter). You should see "Success. No rows returned." for each statement.
5. Click **New query** again.
6. Open `supabase/seed.sql` in this repo. Paste the entire contents and click **Run**.
7. Verify: go to **Table Editor** → `missions`. You should see 52 rows.

---

## Step 3: Configure Google OAuth

1. Go to [console.cloud.google.com](https://console.cloud.google.com).
2. Create a new project (or select an existing one).
3. Go to **APIs & Services → Credentials**.
4. Click **+ Create Credentials → OAuth 2.0 Client ID**.
5. Application type: **Web application**.
6. Name: `1% Better`.
7. Under **Authorized redirect URIs**, add **both**:
   - `https://<your-project-ref>.supabase.co/auth/v1/callback`
     (replace `<your-project-ref>` with the subdomain from your Supabase Project URL)
   - `https://<your-vercel-app>.vercel.app`
     (you will know this URL after Step 8; add it then if you do not know it yet)
8. Click **Create**. Note the **Client ID** and **Client Secret**.
9. In Supabase, go to **Authentication → Providers → Google**.
10. Toggle **Enable Google provider** on.
11. Paste your **Client ID** and **Client Secret** from step 8.
12. Click **Save**.

---

## Step 4: Enable magic-link (email OTP) sign-in

1. In Supabase, go to **Authentication → Providers → Email**.
2. Ensure **Enable Email provider** is toggled on.
3. Ensure **Confirm email** is set based on your preference. For development, disabling email confirmation speeds up testing; re-enable for production.
4. Optionally configure a custom SMTP provider under **Authentication → SMTP Settings** for better email deliverability (e.g. Resend, SendGrid, Postmark). Supabase's built-in mailer has sending rate limits on the free tier.

---

## Step 5: Generate VAPID keys

VAPID (Voluntary Application Server Identification) keys authenticate your server when sending push notifications.

Run this in your terminal (only needs to be done once — do not regenerate unless you delete all push subscriptions):

```bash
npx web-push generate-vapid-keys
```

You will see output like:

```
Public Key:
BExamplePublicKey...

Private Key:
ExamplePrivateKey...
```

Note both values. The **public key** goes in the frontend env var and the edge function secret. The **private key** goes only in the edge function secret and must never be exposed.

---

## Step 6: Set Supabase Edge Function secrets

In your terminal, in the root of this repo, run (with your values substituted):

```bash
supabase secrets set \
  VAPID_PUBLIC_KEY="<your-vapid-public-key>" \
  VAPID_PRIVATE_KEY="<your-vapid-private-key>" \
  VAPID_SUBJECT="mailto:alabinnexus@gmail.com" \
  CRON_SECRET="$(openssl rand -base64 24)" \
  SUPABASE_SERVICE_ROLE_KEY="<service-role-key-from-step-1>"
```

**Important:** The `CRON_SECRET` value generated by `openssl rand -base64 24` will be printed to the terminal output of the above command. Copy it — you will need it again in Step 9. Alternatively, choose your own random string (at least 24 characters).

To verify secrets are set:
```bash
supabase secrets list
```

---

## Step 7: Deploy the Edge Function

From the repo root:

```bash
supabase functions deploy send-nudges
```

After deployment completes, Supabase will print the function URL. It will look like:

```
https://<your-project-ref>.supabase.co/functions/v1/send-nudges
```

Copy this URL — you will need it for Step 9.

To test the function directly:
```bash
curl -X POST \
  -H "x-cron-secret: <your-cron-secret>" \
  "https://<your-project-ref>.supabase.co/functions/v1/send-nudges"
```

Expected response: `{"ok":true,"sent":0}` (0 if no push subscriptions exist yet).

---

## Step 8: Create and configure the Vercel project

1. Go to [vercel.com](https://vercel.com) and sign in.
2. Click **Add New → Project**.
3. Import the GitHub repository `1-better` (or your fork of it).
4. Framework preset: select **Vite**.
5. Build command: `npm run build` (default, do not change).
6. Output directory: `dist` (default, do not change).
7. Under **Environment Variables**, add the following three variables:

   | Name | Value |
   |------|-------|
   | `VITE_SUPABASE_URL` | Your Supabase Project URL from Step 1 (e.g. `https://abcdefgh.supabase.co`) |
   | `VITE_SUPABASE_ANON_KEY` | The anon/public key from Step 1 |
   | `VITE_VAPID_PUBLIC_KEY` | The VAPID public key from Step 5 |

8. Click **Deploy**.
9. After deployment, note your Vercel URL (e.g. `https://1-better.vercel.app`).
10. Go back to Step 3 and add this Vercel URL to your Google OAuth authorized redirect URIs if you had not done so yet.

---

## Step 9: Add GitHub Actions secrets

1. In your GitHub repository, go to **Settings → Secrets and variables → Actions**.
2. Click **New repository secret** for each of the following:

   | Secret name | Value |
   |-------------|-------|
   | `SEND_NUDGES_URL` | The edge function URL from Step 7 (e.g. `https://<ref>.supabase.co/functions/v1/send-nudges`) |
   | `CRON_SECRET` | The same `CRON_SECRET` value set in Step 6 |

---

## Step 10: Enable the GitHub Actions workflow

1. In your GitHub repository, go to the **Actions** tab.
2. If workflows are disabled, click **I understand my workflows, go ahead and enable them**.
3. Find the workflow named **Nudge Cron** (from `.github/workflows/nudge-cron.yml`).
4. Click **Enable workflow** if it is showing as disabled.

The cron will now fire every 15 minutes automatically.

---

## Step 11: Verify the full deployment

1. Open your Vercel URL in a browser.
2. Sign in with Google (or magic-link with your email).
3. You should land on `/today` and see the current week's mission card.
4. Press and hold the button for 1.5 seconds to mark today complete.
5. Verify the day celebration overlay appears.
6. Go to `/journey` and verify the dot grid shows today's activity.
7. Go to `/settings` and verify your profile email is shown.

**To test push notifications:**
1. On the Settings screen, click **Turn on notifications**.
2. Accept the browser permission prompt.
3. Wait for the next 15-minute cron run (check GitHub Actions → Nudge Cron for the next scheduled time), or trigger it manually: go to **Actions → Nudge Cron → Run workflow**.
4. You should receive a push notification if today's habit is not yet marked done.

## Step 12: Install as a PWA (required for push on iPhone)

### iPhone (iOS 16.4+)

1. Open the Vercel URL in **Safari** (not Chrome or Firefox).
2. Tap the **Share** button (box with arrow).
3. Scroll down and tap **Add to Home Screen**.
4. Tap **Add** in the top right.
5. Open the app from your Home Screen.
6. Go to Settings → grant notification permission from within the installed app.

On iPhone, push notifications only work from the Home Screen installed PWA, not from a browser tab.

### Android (Chrome)

1. Open the Vercel URL in **Chrome**.
2. Chrome may show an "Install" banner automatically.
3. If not, tap the menu (three dots) → **Install app** or **Add to Home Screen**.
4. The app installs and opens in standalone mode.
5. Push works from both the installed app and the browser tab on Android.

## Local development

```bash
# Clone the repo
git clone https://github.com/<your-username>/1-better.git
cd 1-better

# Copy env example and fill in your values
cp .env.example .env
# Edit .env: set VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, VITE_VAPID_PUBLIC_KEY

# Install dependencies
npm install

# Start dev server
npm run dev
```

The app runs at `http://localhost:5173`. The service worker is enabled in development (`devOptions.enabled: true` in `vite.config.ts`).

For the Edge Function locally:
```bash
supabase start          # starts local Supabase stack
supabase functions serve send-nudges --env-file supabase/.env.local
```

## Rotating the CRON_SECRET

If the `CRON_SECRET` is ever exposed:

1. Generate a new one: `openssl rand -base64 24`
2. Update the Supabase Edge Function secret: `supabase secrets set CRON_SECRET="<new-value>"`
3. Update the GitHub Actions secret: repo → Settings → Secrets → Actions → `CRON_SECRET` → Update secret.

Both must be updated in sync, or the cron calls will start receiving 401 errors.
